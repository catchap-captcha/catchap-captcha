# 함정이 미리보기 요청 하나로 들통난다 (2026-08-13)

## 요약

봇이 캡차를 **풀기 전에**, 시도를 한 번도 쓰지 않고 함정(honeypot) 전부를 알아낼 수 있다.
객체마다 딸려 오는 미리보기 이미지 주소를 열어보면 **함정만 404** 가 나온다.

실측(운영, 10문항):

| | 결과 |
|---|---|
| 함정 판별 정확도 | **10/10 문항 · 3/3개 전부 적중** (오차 0) |
| 드는 시간 | 문항당 평균 1.2초 (객체 6~7개 순차 요청) |
| 캡차 시도 소모 | **0회** — 이미지 GET 이라 판정에 안 잡힌다 |

`tools/demo_block_direct.mjs` 가 지금 이 방법으로 함정을 피한다.

## 왜 이렇게 되나

문항을 만들 때 진짜 객체만 `captcha_challenge_objects` 에 적는다. 함정은 그 표에 안 들어가고
`captcha_challenges_v2.honeypot_ids` 에만 남는다(`app/main.py` 의 `create_challenge`).

미리보기를 주는 `challenge_asset` 은 그 표에서 찾는다:

```python
mapping = next((m for m in challenge["objects"] if m["temporary_object_id"] == asset_id), None)
if not mapping: raise HTTPException(404, "Asset not found")
```

함정은 표에 없으니 **항상** 404 다. 설정 실수가 아니라 구조가 그렇다.

진짜 객체 쪽에는 예외가 없다 — 객체 35,508개(target 7,366 · decoy 27,023 · invalid 119) 전부
조각 이미지를 갖고 있다. 그래서 `404 = 함정` 이 흔들림 없이 성립한다.

## 무엇이 무너지나

함정의 값어치는 "어느 게 정답인지 모르는 봇만 밟는다" 는 데 있다. 미리 걸러낼 수 있으면
그 전제가 사라진다.

`catchap-infra#58` 로 함정을 1개에서 3개로 올렸고, 근거는 찍기 성공률이었다:

```
객체 2개 + 함정 1개     정답 33% · 함정 33%(봇 확정)
객체 2개 + 함정 3개     정답 20% · 함정 60%(봇 확정)
```

함정을 걸러내면 **둘 다 원래의 50% 로 돌아간다.** 함정을 늘린 효과가 통째로 없어진다.

다만 지금 당장의 피해는 크지 않다. 8월 들어 함정에 걸린 시도는 3,214건 중 42건(1.3%)이고
그중 상당수가 오늘 우리 시연 봇이다. 아직 이 수법을 쓰는 실제 봇은 안 보인다.
**고칠 시간이 있다는 뜻이지, 안 고쳐도 된다는 뜻은 아니다.**

## 어떻게 막나

### ① 함정에도 진짜 같은 조각을 준다 (서버만, 권장)

함정 미리보기를 404 대신 **다른 문항의 진짜 조각**으로 돌려준다.

왜 "다른 문항의 진짜 조각" 인가 — 사진에서 그 자리를 네모로 잘라 주는 방법도 있지만,
진짜 조각은 배경이 뚫린 오려낸 그림(PNG 알파)이고 네모 크롭은 불투명한 사각형이라
그림만 봐도 갈린다. 진짜 조각을 주면 형식으로는 구분할 수 없다.

어느 조각을 줄지는 **함정 임시 id 를 해시해서** 고른다. 저장할 것이 없고(스키마 그대로),
같은 함정은 언제 물어도 같은 그림이 나온다(캐시·재요청에 안전).

주의: 그 임시 id 가 **그 문항의 함정이 맞는지** 확인하고 줘야 한다. 안 그러면 조각을
아무나 받아가는 창구가 된다.

### ② 함정 미리보기를 요청한 것 자체를 봇 신호로 쓴다 (서버만)

화면은 객체를 **집었을 때만** 미리보기를 받는다(끌 때 따라다니는 그림, 정답존에 놓인 그림).
그러니 함정 미리보기 요청은 곧 "함정을 집었다" 는 뜻이고, 그건 이미 봇 확정 행동이다.

여기에 하나를 더한다 — **한 문항에서 서로 다른 함정 미리보기를 2개 이상** 받아가면
자동화로 본다. 사람은 안 보이는 덫을 두 개나 집을 수 없다. 실수로 하나 집는 것과
전부 훑는 것을 이 선이 가른다.

①을 하면 훑어도 아무것도 못 얻으므로 ②는 훑는 쪽을 잡는 그물로 남는다. 둘은 겹치지 않는다.

### ③ 미리보기를 아예 안 준다 (화면까지 고쳐야 함)

원본 사진은 이미 화면에 있으니 조각을 화면에서 잘라 쓰는 방법. 창구가 사라지니 가장 확실하지만,
진짜 조각은 오려낸 그림이라 네모로 자른 것과 보이는 게 달라진다. 지금 화면을 바꿔야 한다.

## 권장

**① + ②.** 둘 다 서버만 고치면 되고, 화면은 손대지 않는다.

①은 공짜로 얻던 정보를 없애고, ②는 그래도 훑는 봇을 잡는다. ③은 화면 작업이 필요해
지금 하기에는 크고, ①이 있으면 급하지 않다.
